Section 0.7: Common Errors and Troubleshooting

Part 0: Getting Started with Python

Errors Tracebacks Common Errors Logic Errors Colab Bug Clinic

Learning Objectives

By the end of this section, you should be able to:

  • distinguish between syntax, runtime, and logic errors;
  • identify the error type and message in a traceback;
  • locate the relevant line of code;
  • diagnose common Python errors;
  • use print() and type() to inspect a program;
  • resolve common Google Colab state and package problems;
  • test a correction without changing unrelated code; and
  • apply a systematic debugging process.

0.7.1 Errors Are Information

Every programmer encounters errors. An error message is not a judgment about the programmer; it is evidence about what Python could not do. Debugging is the process of using that evidence to find and correct a problem.

Error Category Meaning Example
Syntax error Python cannot understand the structure of the code. A missing parenthesis, quotation mark, or colon
Runtime error The code begins running but encounters an invalid operation. Dividing by zero or accessing a missing list element
Logic error The code runs but produces an incorrect result. Using addition where multiplication was required

An Error Message Is Usually a Starting Point

The line named in a traceback is where Python noticed the problem. The underlying cause may be on that line or on an earlier line that created an incorrect value.

0.7.2 Reading a Traceback

When a runtime error occurs, Python displays a traceback. A traceback records the sequence of function calls that led to the error and ends with the error type and message.

Suppose this code is run:

scores = [8, 10, 7]
mean = sum(scores) / count
print(mean)

A simplified traceback looks like this:

---------------------------------------------------------------------------
NameError                                 Traceback (most recent call last)
Cell In[1], line 2
      1 scores = [8, 10, 7]
----> 2 mean = sum(scores) / count
      3 print(mean)

NameError: name 'count' is not defined

Read from the Bottom Up

  1. Read the final line: NameError is the error type.
  2. Read the message: count has not been defined.
  3. Find the highlighted line where Python detected the problem.
  4. Inspect the variables used on that line.
  5. Make the smallest reasonable correction.
  6. Run the cell again and check the result.

One correction is:

scores = [8, 10, 7]
count = len(scores)
mean = sum(scores) / count
print(mean)

Do Not Change Code at Random

Random edits can hide the original cause or introduce new errors. Use the traceback to form a specific explanation, then test one correction at a time.

0.7.3 SyntaxError

A SyntaxError means that Python cannot parse the code. The program does not begin running.

Missing Parenthesis

# Incorrect
print("MATH 1516"

# Correct
print("MATH 1516")

Missing Quotation Mark

# Incorrect
course = "MATH 1516

# Correct
course = "MATH 1516"

Missing Colon

# Incorrect
for value in [1, 2, 3]
    print(value)

# Correct
for value in [1, 2, 3]:
    print(value)

The caret symbol in a syntax message points near the place where Python became unable to continue. Check the indicated position and the code immediately before it.

0.7.4 IndentationError

Indentation identifies the body of a loop, function, or conditional block. Inconsistent or missing indentation can produce an IndentationError. 

# Incorrect
for value in [1, 2, 3]:
print(value)

# Correct
for value in [1, 2, 3]:
    print(value)

A second common problem is accidentally placing too much code inside a loop:

# The total is printed during every iteration.
total = 0

for value in [1, 2, 3]:
    total = total + value
    print("Final total:", total)

# The final result is printed once after the loop.
total = 0

for value in [1, 2, 3]:
    total = total + value

print("Final total:", total)

Indentation Can Cause a Logic Error

The first version is valid Python, so no exception occurs. Its indentation changes the program's behaviour and produces three output lines instead of one.

0.7.5 NameError

A NameError occurs when Python cannot find a variable or function with the requested name. 

# Incorrect: the variable was defined as score.
score = 18
print(Score)

# Correct
score = 18
print(score)

Common causes include:

  • a spelling mistake;
  • different capitalization;
  • using a variable before assigning it;
  • forgetting to run the cell that defines it; or
  • restarting a Colab runtime and losing stored variables.

Check a Missing Name

  1. Copy the missing name from the final traceback line.
  2. Search the notebook for where it should be defined.
  3. Compare the spelling and capitalization exactly.
  4. Run the definition cell before the cell that uses the name.

0.7.6 TypeError and ValueError

TypeError

A TypeError occurs when an operation receives a value of an inappropriate type. 

# Incorrect: input() returns a string.
age = input("Enter your age: ")
next_age = age + 1

# Correct
age = int(input("Enter your age: "))
next_age = age + 1

Use type() to inspect a value:

age = input("Enter your age: ")
print(age)
print(type(age))

ValueError

A ValueError occurs when the type of an argument is acceptable, but its value cannot be processed as requested. 

number = int("twelve")

The argument is a string, which int() accepts, but the characters in "twelve" do not represent an integer. Use int("12") or enter numerical input.

Error Question to Ask
TypeError Are the operands or arguments the expected types?
ValueError Can this particular value be converted or processed?

0.7.7 Index and Arithmetic Errors

IndexError

values = [4, 7, 9]
print(values[3])

The valid indices are 0, 1, and 2. Use values[2] for the third element or values[-1] for the last element.

Useful checks include:

print("Length:", len(values))
print("Requested index:", 3)

ZeroDivisionError

scores = []
mean = sum(scores) / len(scores)

The empty list has length zero. A mean is not defined for an empty dataset, so the program must obtain data before performing the calculation. 

scores = [8, 10, 7]
mean = sum(scores) / len(scores)
print(mean)

0.7.8 Import and Package Errors

ModuleNotFoundError

This error means that Python cannot find the requested package or module in the current environment. 

ModuleNotFoundError: No module named 'sympy'

In Google Colab:

%pip install sympy
import sympy as sp

Also check:

  • the spelling of the package and module name;
  • whether the runtime was recently reset;
  • whether the installation cell ran successfully; and
  • for local work, whether the editor selected the same Python environment where the package was installed.

ImportError or Missing Name

A package may exist while a requested name does not. Check the import statement and the package's documented spelling.

Check Your Filenames

Do not name your own file numpy.py, pandas.py, sympy.py, random.py, or another package name. Python may import your file instead of the intended module.

0.7.9 Logic Errors

A logic error does not necessarily produce a traceback. The program runs, but the answer is wrong. Mathematical reasoning and carefully selected tests are essential for detecting these errors.

Example: Incorrect Mean

scores = [6, 8, 10]
mean = sum(scores) / 2
print(mean)

The code runs and prints 12.0, but there are three values. The denominator should be len(scores): 

mean = sum(scores) / len(scores)

Test with a Known Answer

Choose a small input whose correct result can be calculated by hand. A mean function can be tested with [2, 4, 6], whose mean is 4. 

def calculate_mean(values):
    return sum(values) / len(values)

test_values = [2, 4, 6]
print("Expected: 4")
print("Actual:", calculate_mean(test_values))

Inspect Intermediate Values

radius = 5
pi = 3.14159
area = 2 * pi * radius ** 2  # Incorrect formula

print("radius =", radius)
print("radius squared =", radius ** 2)
print("area =", area)

Temporary print statements help identify the first point where the actual calculation differs from the intended mathematics. Remove or simplify them after the problem is resolved.

0.7.10 Troubleshooting Google Colab

Symptom Likely Cause Action
A variable is missing Its cell was not run, or the runtime restarted Run the definition cell, then run cells from top to bottom.
Old output remains visible The code changed but the cell was not rerun Run the edited cell and any dependent cells again.
Results change unexpectedly Cells were executed out of order Restart the session and run all cells in order.
A custom package disappeared A new temporary runtime was assigned Rerun the installation and import cells.
A cell runs indefinitely An infinite loop or slow calculation Stop the cell and inspect the loop condition.
The runtime disconnected Inactivity, session limits, or a browser/network interruption Reconnect and rerun the notebook from the beginning.

Clean Notebook Test

  1. Save the notebook.
  2. Restart the runtime or session.
  3. Run all cells from top to bottom.
  4. Stop at the first error rather than continuing past it.
  5. Confirm that the displayed outputs match the current code.

If a notebook only works after cells are run in a special order, it is not yet reproducible. Move definitions and setup cells before the code that uses them.

0.7.11 A Systematic Debugging Process

Debugging Checklist

  1. Reproduce the problem. Run the smallest relevant cell or code block.
  2. Read the final traceback line. Record the error type and message.
  3. Locate the line. Inspect the highlighted instruction and nearby definitions.
  4. Check names and types. Verify spelling, capitalization, values, and type().
  5. Check the mathematics. Compare the implemented formula with the intended one.
  6. Simplify. Replace complicated input with a small known example.
  7. Make one change. Test a specific correction.
  8. Rerun dependencies. In Colab, execute required earlier cells.
  9. Test again. Use both an ordinary case and an edge case.
  10. Run from the beginning. Confirm the complete notebook is reproducible.

Reduce the Problem

If a long program fails, create a smaller example that still produces the same error. For example, replace a large dataset with three values. This removes distractions and makes the cause easier to see.

Ask for Help Effectively

When asking a tutorial leader or classmate for help, provide:

  • the smallest code that reproduces the problem;
  • the complete error type and message;
  • what you expected to happen;
  • what actually happened; and
  • the corrections you already tried.

Do Not Share Secrets

Before sharing a notebook or screenshot, remove passwords, API keys, private links, student information, and other sensitive data.

0.7.12 Handling Expected Input Errors

Some errors can be anticipated. A try and except block allows a program to respond to a specific exception. 

try:
    radius = float(input("Enter the radius: "))
    area = 3.14159 * radius ** 2
    print(f"Area: {area:.2f}")
except ValueError:
    print("Please enter a numerical value.")

Only the statements that might raise the expected error belong inside the try block. Catch the specific error type rather than hiding every possible exception.

Exception Handling Does Not Replace Debugging

Do not surround an entire notebook with a broad except block. Unexpected errors should remain visible so their causes can be corrected.

0.7.13 Tutorial Activity: Python Bug Clinic

Diagnose Before You Repair

For each program below:

  1. predict the error type or incorrect output;
  2. identify the line that causes the problem;
  3. explain the cause in one sentence;
  4. make the smallest correction; and
  5. run the corrected program in Colab.

Bug A

values = [2, 4, 6]
print(values[3])

Bug B

score = input("Enter the score: ")
percentage = score / 20 * 100
print(percentage)

Bug C

def square(x):
return x ** 2

print(square(5))

Bug D

numbers = [1, 2, 3, 4]
mean = sum(numbers) / 3
print(mean)

Bug E

import numpy as np

values = np.array([1, 2, 3])
print(numpy.mean(values))
Show diagnoses and corrections

Bug A

IndexError: index 3 refers to a nonexistent fourth element. Use values[2] or values[-1].

Bug B

TypeError: input() returned a string. Convert the input using float(input(...)).

Bug C

IndentationError: the return statement must be indented beneath the function header.

Bug D

Logic error: four numbers are divided by 3. Use sum(numbers) / len(numbers).

Bug E

NameError: NumPy was imported using the alias np. Use np.mean(values).

0.7.14 Concept Check

  1. What is the difference between a runtime error and a logic error?
  2. Which part of a traceback should usually be read first?
  3. What does a NameError indicate?
  4. Why can numerical input produce a TypeError?
  5. What is a useful test input for a mean function?
  6. Why should a Colab notebook be restarted and run from top to bottom?
  7. Why should only one suspected problem be changed at a time?
Show suggested answers
  1. A runtime error stops execution with an exception; a logic error allows execution but produces the wrong result.
  2. The final line, which gives the error type and message.
  3. Python cannot find the requested variable or function name.
  4. input() returns a string unless the result is converted.
  5. A small list with an easily verified mean, such as [2, 4, 6].
  6. It reveals missing setup, hidden state, and cells that depend on an unusual execution order.
  7. Changing one factor makes it possible to determine whether that correction solved the problem.

0.7.15 Practice Exercises

  1. Correct the syntax error in print("Result:", 4 ** 2.
  2. Correct the name error in radius = 3; print(radiuss).
  3. Explain why float("3.5") works but int("3.5") raises a ValueError.
  4. Correct the index error in letters = ["a", "b"]; print(letters[2]).
  5. Find the logic error in a rectangle-area calculation that uses 2 * (length + width).
  6. Write two test cases for a function that calculates the square of a number.
  7. Create a short debugging report containing the error type, cause, correction, and successful test.
Show sample solutions
  1. Add the closing parenthesis: print("Result:", 4 ** 2).
  2. Use the defined name: print(radius).
  3. "3.5" represents a valid floating-point number but not a base-10 integer literal. One conversion is int(float("3.5")), which gives 3.
  4. Use letters[1] or letters[-1].
  5. The expression calculates perimeter. Rectangle area is length * width.
  6. For example, square(3) should return 9 and square(-2) should return 4.
  7. A complete report should identify one reproducible problem and show that the corrected code gives the expected result.

Section Summary

  • Syntax errors prevent Python from understanding the code.
  • Runtime errors occur during execution and produce exceptions.
  • Logic errors produce incorrect results without necessarily producing a traceback.
  • Read the final traceback line first, then inspect the highlighted code.
  • Common exceptions include NameError, TypeError, ValueError, IndexError, and ZeroDivisionError.
  • Use small known examples, print(), and type() to inspect a program.
  • Colab notebooks should run correctly from top to bottom after a clean restart.
  • Effective debugging changes one suspected cause at a time and verifies the correction.
